# hokan-website

The Hokan marketing site: static HTML, no framework, no build dependencies.

The pages are generated from the Claude Design canvas export that lives in this
repo, so the design stays the source of truth and the deployed HTML stays plain.

## Layout

| Path | What it is |
| --- | --- |
| `index.html`, `how-it-works.html`, `architecture.html`, `use-cases.html`, `pricing.html`, `trust.html` | The deployed site. Generated — do not hand-edit. |
| `assets/site.css` | The stylesheet. Hand-written; every class the build emits is defined here. |
| `assets/tokens.css` | Design tokens, compiled from `_ds/**/tokens/`. Generated. |
| `assets/site.js` | Progressive enhancement: the small-screen menu. The site works without it. |
| `assets/*.svg` | Logo mark, Cardano lockup, favicon. |
| `assets/og/*.png` | Per-page Open Graph cards, 1200x630. Generated. |
| `sitemap.xml`, `robots.txt` | Generated by the build. |
| `tools/build.mjs` | The build. Node 18+, no dependencies. |
| `tools/pages.mjs` | Site config: canonical origin, nav, per-page titles and descriptions. |
| `tools/diagrams/*.html` | The technical diagrams, as inline SVG partials. |
| `tools/og-image.mjs`, `tools/og-template.html`, `tools/fonts/` | Open Graph card renderer. Needs Playwright; not part of the normal build. |
| `*.dc.html`, `_ds/`, `support.js` | The Claude Design canvas export. The design source. |

## Build

```sh
node tools/build.mjs
```

It reads each `*.dc.html` artboard and writes the matching `.html` page:

1. lifts the markup out of the `<x-dc>` canvas wrapper
2. renders the `<x-import>` design-system components (TopBar, Button, Card) as real HTML
3. replaces every generated inline style with a class from `assets/site.css`, swaps
   in the shared footer, and drops each `tools/diagrams/*.html` partial into the
   `<div data-diagram="...">` slot that names it
4. drops the "note before publishing" blocks (`SHOW_NOTES = false`)
5. wraps the page in a document with `<head>`, a skip link, a `<main>` landmark and the footer
6. compiles `_ds/**/tokens/*.css` into `assets/tokens.css`
7. writes `sitemap.xml` and `robots.txt`

Page titles, meta descriptions, the canonical origin, the nav, the footer columns
and the parent-company details all live in `tools/pages.mjs` — edit them there,
not in the generated HTML.

## Diagrams

Each diagram is a `<figure class="diagram">` in `tools/diagrams/`, hand-authored
as inline SVG: no library, no runtime, no external image. A page pulls one in
with a slot in its design source:

```html
<div data-diagram="lifecycle"></div>
```

They are inline rather than `<img>` so they can take their colours from the
design tokens, which is what makes them work in both themes. Style them with the
`dg-` classes in `assets/site.css` rather than presentation attributes:
`dg-surface` for a box, `dg-surface--accent` for the one that holds funds,
`dg-surface--strong` for a settled state, `dg-line` / `dg-line--quiet` for solid
and dashed edges, `dg-label` / `dg-note` for text, `dg-zone` for a boundary.

Rules that keep them readable: label every arrow, keep `<text>` at 11-13px in the
viewBox's own units, and give each `<svg>` a `role="img"` and an `aria-label` that
states the same claim as the caption. Below about 660px a diagram scrolls
sideways inside `.diagram__viewport` rather than shrinking its labels to nothing.

## Page transitions

Navigating between pages cross-fades. Browsers with cross-document view
transitions do it from CSS alone (`@view-transition` in `assets/site.css`), and
everywhere else a small block in `assets/site.js` fades the page out on click and
the CSS fades the next one in. Both paths honour `prefers-reduced-motion`, and
with JavaScript off the links simply navigate.

An inline style with no class mapped to it fails the build and names the rule.
That is deliberate: when the design changes, the build tells you exactly what
needs a class rather than silently shipping a page that looks wrong.

## Changing the design

Edit the design in Claude Design, export it over the `*.dc.html` files and
`_ds/`, run the build, and commit both the sources and the generated pages.
For a change that is purely presentational — spacing, colour, a breakpoint —
edit `assets/site.css` directly and rebuild.

## What the build adds on top of the canvas

The artboards are fixed-width design surfaces; these are the things a shipped
page needs that a canvas does not have.

- Responsive nav: below 860px the primary nav collapses behind a Menu button
  (`assets/site.js`). Without JavaScript the nav simply stays expanded.
- Dark mode by system preference, mirroring `[data-theme="dark"]` from the
  design tokens. The bands the design marks `data-theme="dark"` stay dark
  in both modes.
- Accessibility: one `<main>` landmark per page, a skip link, `aria-current`
  on the active nav item, focus-visible rings from the token base styles.
- `<head>`: title, meta description, Open Graph and Twitter card tags, SVG
  favicon, and Google Fonts loaded with `<link rel=preconnect>` rather than
  the token file's `@import`.
- Wide tables scroll inside their own container instead of pushing the page
  sideways on a phone.

## SEO

- Per-page `<title>` and meta description, both kept inside the length search
  engines actually render, in `tools/pages.mjs`.
- `<link rel="canonical">` and `og:url` on every page, absolute against
  `SITE_URL`.
- Open Graph and Twitter card tags, including a real 1200x630 image per page
  with `og:image:width`, `og:image:height` and `og:image:alt`, so links unfurl
  as a large card rather than a bare title.
- Schema.org JSON-LD: `Organization` and `WebSite` on the home page, and a
  `FAQPage` on the trust page built from the questions actually on it — so it
  cannot drift from the visible copy.
- `sitemap.xml` listing all six pages, and a `robots.txt` that points at it and
  keeps crawlers out of the design sources (`_ds/`, `tools/`, `*.dc.html`).
- `theme-color` for light and dark, one `<h1>` per page, descriptive link text,
  and `alt` on every meaningful image.
- No dead links anywhere: anything not written yet (docs, API reference, sandbox,
  contracts, status) renders as a label with a Soon pill rather than an anchor
  that goes nowhere. Set `soon: true` on a nav or footer entry in
  `tools/pages.mjs`, or use `<span data-btn="soon">` in a design source, and give
  it a real `href` when the page exists.

### Regenerating the Open Graph cards

The cards render in a browser, so they are not part of `tools/build.mjs`. After
changing a page's `og.title` or `og.tagline`:

```sh
npm install playwright && npx playwright install chromium
node tools/og-image.mjs
```

Then commit the PNGs. The card fonts are vendored in `tools/fonts/` (SIL Open
Font Licence) so the render does not depend on a network call.

## Deployment

Static files at the repository root — push to `main` and the host serves it.
`.nojekyll` stops GitHub Pages' Jekyll pass from dropping `_ds/`.
